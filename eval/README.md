# Эталоны и сверка

`synthetic.json` содержит только вымышленные сценарии. Идентификаторы SYN не ссылаются на реальные документы; факты являются тестовыми предположениями, а не правилами организации. По каждому из 11 сценариев предполагается вымышленный фрагмент p1 с текстом из required_facts; в случае конфликта SYN-12#p1 и SYN-12#p2 содержат два разных срока. Эти фикстуры ещё не импортированы в приложение, оценка качества ответов не проводилась.

Шаблон записи AC: `id`, `topic`, `question`, `conditions` (список), `required_facts` (список), `forbidden_conclusions` (список), `expected_fragments` (список устойчивых идентификаторов), `status`. Для отсутствующих данных или сбоя список фрагментов может быть пустым. Валидатор предназначен для синтетического набора.

Для реального эталона владелец локально создаёт запись в `data/runs/` по тому же шаблону, со статусом `pending_owner_review`, и добавляет поля: `source_id`, `original_checksum`, `locator` (страница и пункт, либо таблица/лист и координаты), `owner_confirmation`, `review_date`, `actual_result`, `result`. Он сверяет по оригиналу текст, границы фрагмента, обязательные факты и числа, условия и исключения, редакцию и дату, наличие приложений, статус утверждения и отсутствие недопустимых выводов; затем фиксирует результат и подтверждение. Не переносить содержимое или цитаты в чат. Эталоны AC из SDD остаются планом до этой сверки.

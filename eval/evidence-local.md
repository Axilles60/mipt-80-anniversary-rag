# Локальная проверка владельцем данных

В текущей сессии оригиналы не сверялись. Перед прогоном владелец импортирует корпус по инструкции README, сверяет оригиналы и создаёт локальные файлы `data/runs/evidence-catalog.json` и `data/runs/evidence-cases.json`. Формат каталога демонстрирует `fixtures/evidence/synthetic.json`: даты ISO, интервалы включительные; `null` означает неизвестную или не заданную границу. Каждый документ и фрагмент имеют идентификатор, локатор и текст; для каждого правила указан фрагмент, вид (`norm`, `form`, `example`, `instruction`, `historical_task`), период, условия и исключения. `conditions` и `exceptions` — отображения строковых имён условий в значения. Связь содержит `origin`, `target`, тип и ID фрагмента-основания; для изменения пункта и конфликта origin/target — ID правил, для остальных — ID документов. Направление изменения: origin изменяет target. Для пропуска цепочки и отсутствующего приложения добавить отдельное `limits` с основанием. Каталог заполняется вручную; в веб-ветке импортированного каталога ID, текст и локатор сверяются с импортом; это не подтверждает даты, связи и содержательную верность. Владелец должен проверить контрольную сумму версии, локатор, текст, даты, область действия, связь и её основание по оригиналу; значение формы не отмечать как норму.

Формат файла сценариев — JSON-массив записей: `id`, `question`, `date`, `conditions`, `expected_fragments`, `forbidden_fragments`, `expected_limit_fragments`, `expect_conflict`, `expect_question`. Списки содержат ID фрагментов каталога. Пример формы без реальных реквизитов: `[{"id":"LOCAL-01","question":"вопрос","date":"2021-01-01","conditions":{"категория":"пример"},"expected_fragments":["ID"],"forbidden_fragments":[],"expected_limit_fragments":[],"expect_conflict":false,"expect_question":false}]`.

Для AC-SYS-05 подготовить исторические и новые даты, отдельный пункт изменения и неопределённую промежуточную редакцию. Для AC-SYS-06 — пустые реквизиты, отсутствующие приложения, отсутствующую инструкцию и ошибочную формулу; дополнительно вручную проверить то, что этот механизм не анализирует автоматически. Для AC-DEMO-02 — условия обычной многодневной командировки, сроки, роли, статус утверждения и отсутствие форм; проверить каждый факт и ссылку по оригиналу. Нельзя считать проверку идентификаторов доказательством полноты ответа.

Команда: `.venv/bin/python eval/run_evidence.py data/runs/evidence-catalog.json data/runs/evidence-cases.json --report data/runs/evidence-results.json`. В stdout только агрегаты; подробный отчёт хранится локально. По окончании владелец вручную фиксирует результат и дату сверки в `data/runs/`; провал, незаполненная проверка или отсутствие оригинала не является успешной приёмкой. Для веб-проверки загрузить каталог командой `.venv/bin/python -m app load-evidence data/runs/evidence-catalog.json`, запустить сервис и задать вопрос с датой и категорией. Загрузка заменяет курируемый каталог целиком: сохраните его резервную копию до обновления.

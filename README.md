# Навигатор сотрудника

Локальный сервис вопросов и ответов по внутренним регламентам организации. Сотрудник спрашивает обычными словами. Сервис находит нужные пункты документов, собирает ответ локальной моделью и показывает только то, что код подтвердил по тексту документа, со ссылкой на место в документе. Если ответа в документах нет, сервис так и говорит; на вопрос не по работе — что это вне его базы.

Всё работает на одной машине: внешних сервисов нет, документы и вопросы её не покидают.

## Быстрый старт

1. Положите документы в `data/originals/`: PDF (с текстом или сканы), DOCX, XLSX или ZIP с ними, можно во вложенных папках.
2. Запустите из корня проекта:

   ```sh
   docker compose --profile gpu up --build     # NVIDIA ≥ 6 ГБ, CUDA 12.4+, NVIDIA Container Toolkit
   docker compose --profile cpu up --build     # без видеокарты
   ```

   В Linux, чтобы контейнер мог писать в `data/index/`, добавьте в начало команды `NAVIGATOR_UID=$(id -u) NAVIGATOR_GID=$(id -g)`.
3. Дождитесь в журнале строки `Import finished …` и откройте http://127.0.0.1:8000/.

Модели скачиваются при сборке и сверяются по SHA-256 (`tools/fetch_model.py`):

| Модель | Назначение | Размер |
| --- | --- | --- |
| `multilingual-e5-small` (ONNX) | векторы для смыслового поиска | ≈ 490 МБ |
| `bge-reranker-v2-m3` int8 | переупорядочивание найденного | ≈ 570 МБ |
| `Qwen3-4B-Instruct-2507` Q4_K_M | генерация ответа | ≈ 2.5 ГБ |

Повторный старт пропускает неизменённые файлы. Изменённый файл становится новой версией документа. Файлы других форматов не импортируются и перечисляются в журнале строкой `Not imported`.

## Архитектура

```text
 data/originals ──► импорт ──► SQLite: оригиналы, фрагменты, реквизиты, чанки, FTS5, векторы, история
                                         │
 браузер ─вопрос─► диалог ─► поиск BM25 + E5 ─► reranker ─► генератор (JSON) ─► проверка кодом ─► ответ
```

Один процесс Python (многопоточный веб-сервер, импорт, поиск) и один файл SQLite. Генератор — `llama-server` из llama.cpp: в профиле GPU это отдельный контейнер, его порт наружу не публикуется; в профиле CPU модель работает внутри процесса. Запросы к генератору идут только на локальный адрес, мимо прокси, без перенаправлений.

| Модуль | Что делает |
| --- | --- |
| `app/autoimport.py`, `app/importer.py` | Импорт папки при старте: контрольные суммы и версии, текст PDF и OCR сканов (Tesseract), абзацы, таблицы и сноски DOCX, ячейки XLSX. Оригинал хранится в базе. |
| `app/requisites.py` | Реквизиты документа (вид, номер, дата) и связи редакций: «изменяет», «отменяет». |
| `app/chunking.py` | Чанки по пунктам и разделам. Строка таблицы — с заголовками столбцов и подписью; объединённые ячейки заполняются; в иерархических таблицах пустая ячейка владельца берёт ближайшее значение выше. |
| `app/retrieval.py`, `app/dense.py`, `app/chunk_search.py` | BM25 (FTS5, основы слов, сокращения из корпуса) и векторы E5, объединённые RRF; только редакции, действующие на дату вопроса. |
| `app/rerank.py` | Cross-encoder переупорядочивает 20 лучших чанков; низкая оценка — отказ до генерации. |
| `app/rag.py` | Контекст, генерация по JSON-схеме, проверка утверждений, ложные посылки, «вне темы», переписывание уточнений. |
| `app/history.py` | История диалога по браузеру (cookie) и связь вопроса с предыдущими. |
| `app/__main__.py` | Веб-интерфейс и команды `import`, `audit`, `embed`. |

### Как отвечается вопрос

1. **Диалог.** Код решает, новый это вопрос или уточнение («а для руководителей?», «их», «там»). Уточнение модель переписывает в самостоятельный вопрос. Код проверяет переписанное: оно остаётся вопросом, не добавляет чисел, отрицаний и слов, которых не было в диалоге. Иначе берутся слова самого человека — предыдущий вопрос и текущий. Под ответом видно «Понял вопрос как …» и есть кнопка «Это новый вопрос».
2. **Поиск** по редакциям, действующим на дату вопроса, затем reranker. Для многошаговых вопросов («кто финансодержатель подразделения X») — второй шаг поиска по найденному.
3. **Генерация.** Qwen3-4B отвечает по JSON-схеме: утверждения с номерами фрагментов. Текст документов в подсказке — данные, а не инструкции.
4. **Проверка кодом** каждого утверждения по процитированному фрагменту:
   - числа, даты, номера, телефоны, инициалы, адреса — целыми токенами;
   - единица и направление границы («не менее 12 часов» ≠ «не более 12 дней»);
   - знак («не запрещено» по тексту «запрещено» не проходит);
   - «в документах не указано» — только если документ сам так говорит;
   - слова предмета вопроса должны быть во фрагменте.

   Неподтверждённое утверждение удаляется. Если не осталось ни одного — ответ «Недостаточно данных».
5. **Ложная посылка.** Если вопрос называет величину, которой нет в документе о том же предмете («почему суточные 1000?»), показывается дословное предложение документа.
6. **Вывод:** ответ (нумерованный список — только для порядка действий), дословные фрагменты со ссылками на место в документе, источники и ограничения (реквизиты, изменения и отмена редакций). Можно открыть документ целиком и исходный файл.

Если модель не дала ответа, страница говорит почему (недоступна, неверный формат, ответ оборвался, слишком много фрагментов) и показывает найденные фрагменты без обработки. Ответ длиннее 1200 токенов не теряется: показываются его целые проверенные утверждения с пометкой. Пока идёт импорт, сайт отвечает страницей «Идёт загрузка документов».

## Качество

Золотой набор — 16 вымышленных регламентов (`fixtures/rag`) и размеченные вопросы: факты, таблицы, сроки, многошаговые и составные вопросы, редакции по дате, ложные посылки, вопросы без ответа и вне темы, опечатки, попытки инъекций. Оценщик — `eval/measure_rag.py`, RTX 4090:

| Набор | Вопросов | Верно | Ложных | Неполных | Пропусков | Медиана / 95% |
| --- | --- | --- | --- | --- | --- | --- |
| tuning | 176 | 162 | 2 | 4 | 8 | 1.3 / 2.4 с |
| holdout v2 | 60 | 56 | 0 | 0 | 4 | 1.2 / 2.6 с |
| holdout v3 | 65 | 56 | 2 | 2 | 5 | 1.1 / 2.2 с |

Без генератора (только поиск и цитаты) на tuning было 52 ложных ответа против 2. Диалоги (`eval/dialogue_scan.py`): связь вопросов 20/20, понимание уточнения 20/20. Тесты: `python -m unittest discover -s tests` (235, около 3 мин).

**Чего эти цифры не доказывают.** Корпус вымышленный. Holdout v2 и v3 — регрессионные наборы: по их ошибкам вносились правки, поэтому это не независимая оценка; для неё нужен новый закрытый набор, прогоняемый один раз. Разбор по итерациям — в [журнале качества](sdd/quality-progress.md).

## Ограничения

- **Отказ вместо ответа.** Сервис скорее откажет, чем покажет неподтверждённое; часть отказов — при существующем ответе.
- **Сложная структура документов.** Пункт перечня без вводной фразы, групповые строки справочников, бланки XLSX со сложной шапкой, сокращения без расшифровки в тексте, плохие сканы. Номер и дата документа иногда берутся из ссылки в тексте, а не из шапки.
- **Модель на 4 млрд параметров** плохо справляется с расчётами и сопоставлением многих документов.
- **Редакции** распознаются по типовым формулировкам («внести изменения», «признать утратившим силу»).
- **Форматы:** PDF, DOCX, XLSX, ZIP. DOC, XLS, RTF, ODT, HTML нужно пересохранить.
- **Нет авторизации и разграничения прав:** порт по умолчанию открыт только на `127.0.0.1`. Для закрытых данных нужны вход и права доступа.

## Настройки

Основные переменные (полный список — в `Dockerfile` и `docker-compose.yml`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NAVIGATOR_PIPELINE` | `rag` в compose | `rag` или `extractive` (только поиск и цитаты) |
| `NAVIGATOR_RETRIEVAL` | `hybrid` в compose | `bm25`, `hybrid`, `dense` |
| `NAVIGATOR_LLM_URL` | `http://llm:8080` (GPU) | адрес `llama-server`, только локальный |
| `NAVIGATOR_IMPORT_DIR` | `/data/originals` | папка, импортируемая при старте |
| `NAVIGATOR_DB` | `/data/index/navigator.sqlite3` | файл базы |
| `NAVIGATOR_ABSTAIN` | `0.003` | порог reranker для отказа до генерации |
| `NAVIGATOR_HISTORY`, `NAVIGATOR_HISTORY_WINDOW` | `1`, `120` | история диалога и её окно в минутах |
| `NAVIGATOR_OCR_DPI`, `NAVIGATOR_OCR_LANG`, `NAVIGATOR_OCR_TESSDATA` | `300`, `rus+eng`, — | OCR сканов |
| `HOST`, `PORT` | `0.0.0.0`, `8000` | адрес прослушивания |

## Без Docker

Нужны Python 3.11+ и Tesseract (`rus`, `eng`, `osd`):

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dense.txt
python tools/fetch_model.py e5 data/models/multilingual-e5-small
python tools/fetch_model.py reranker data/models/bge-reranker-v2-m3
python tools/fetch_model.py qwen3 data/models/qwen3-4b-instruct-2507
llama-server -m data/models/qwen3-4b-instruct-2507/Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf -ngl 99 -c 32768 -np 2 --port 8081
NAVIGATOR_PIPELINE=rag NAVIGATOR_RETRIEVAL=hybrid NAVIGATOR_LLM_URL=http://127.0.0.1:8081 NAVIGATOR_IMPORT_DIR=data/originals python -m app
```

Генератор на CPU внутри процесса: `pip install -r requirements-rag.txt` (нужны компилятор C/C++ и cmake) и запуск без `NAVIGATOR_LLM_URL`.

Демосервер работает из чистого клона этого репозитория (`git status` пуст): данные, модели и окружение Python лежат вне клона и передаются переменными окружения. Выкладка — `git fetch` и `git reset --hard origin/<ветка>` с перезапуском; на сервере всегда тот же коммит, что на GitHub.

# Навигатор сотрудника

Сотрудник задаёт вопрос о внутренних регламентах. Сервис:
- находит нужные пункты документов;
- собирает ответ локальной моделью;
- проверяет кодом каждое утверждение по процитированному тексту;
- показывает ссылки на фрагменты с выделенным местом.

Если в документах ответа нет, сервис прямо так и говорит. На вопрос не по работе отвечает, что это вне его базы.

Документы импортируются кодом при старте контейнера. Всё работает на этой машине: внешних сервисов нет, документы и вопросы её не покидают. Оговорка: запрос к генератору пока использует прокси из переменных окружения (`HTTP_PROXY`) — не задавайте их контейнеру; исправление запланировано.

Качество измерено на вымышленных документах (раздел [«Качество»](#качество)). На реальном корпусе его подтверждает владелец данных: [метрики на оригиналах](eval/owner-acceptance.md). Статус критериев приёмки — в [матрице приёмки](eval/acceptance-matrix.md).

## Требования к окружению

| | GPU (рекомендуется) | CPU |
| --- | --- | --- |
| ОС | Linux или Windows 10/11 с Docker Desktop на WSL2 | Linux, Windows или macOS |
| Docker | Docker Engine 24+ или Docker Desktop с Compose v2 | то же |
| Оборудование | NVIDIA с ≥ 6 ГБ видеопамяти (генератор занимает около 5 ГБ; проверено на RTX 5070 Laptop, 8 ГБ); драйвер с CUDA 12.4+; NVIDIA Container Toolkit (в Docker Desktop — поддержка GPU в WSL2) | 4+ ядра, ≥ 8 ГБ ОЗУ (генератор — около 5 ГБ) |
| Диск | около 12 ГБ: образы, модели, индекс (оценка) | около 7 ГБ (оценка) |
| Время ответа | 3–4 с по медиане, до 8 с (95-й процентиль); зависит от состояния GPU | порядка 30–60 с (оценка, не замер) |
| Сеть | только при сборке образов: базовые образы, пакеты, модели | то же |

Модели скачиваются при сборке и сверяются по SHA-256 (`tools/fetch_model.py`):
- `multilingual-e5-small` (ONNX, ≈490 МБ) — эмбеддинги для смыслового поиска;
- `bge-reranker-v2-m3` int8 (≈570 МБ, Apache-2.0) — переупорядочивание найденного;
- `Qwen3-4B-Instruct-2507` Q4_K_M (≈2.5 ГБ, Apache-2.0) — генератор ответа.

Внешние сервисы при работе: нет. При сборке используются Docker Hub (`python:3.13-slim`), GitHub Container Registry (`ghcr.io/ggml-org/llama.cpp:server-cuda`, закреплён по digest), PyPI, репозиторий пакетов Debian и Hugging Face (модели).

## Запуск и остановка

1. Положите документы (PDF, DOCX, XLSX или ZIP с ними, можно во вложенных папках) в `data/originals/`.
2. Соберите и запустите (из корня проекта):

   ```sh
   docker compose --profile gpu up --build
   ```

   Без видеокарты NVIDIA: `docker compose --profile cpu up --build`.

3. Дождитесь в журнале строки `Import finished …: ok …, review …, error …`. Затем откройте http://127.0.0.1:8000/ — интерфейс доступен только с этой машины.

Остановка: `Ctrl+C` в окне запуска или `docker compose --profile gpu down` (для CPU — `--profile cpu`). Индекс остаётся в `data/index/`.

**Linux.** Контейнер работает от непривилегированного пользователя. Чтобы он мог писать в `data/index/`, запускайте так:

```sh
mkdir -p data/originals data/index
NAVIGATOR_UID=$(id -u) NAVIGATOR_GID=$(id -g) docker compose --profile gpu up --build
```

**Повторный запуск.** Неизменённые файлы пропускаются по контрольной сумме (`unchanged`). Изменённый файл становится новой версией документа, новый — добавляется; правка кода не нужна. Повреждённый или неподдерживаемый файл получает статус `error` с причиной и не мешает остальным.

**Без compose** — один контейнер, генератор на CPU:

```sh
docker build --build-arg WITH_RAG=1 --build-arg PIPELINE=rag --build-arg RETRIEVAL=hybrid -t employee-navigator:rag .
docker run --rm --name employee-navigator -p 127.0.0.1:8000:8000 --user "$(id -u):$(id -g)" \
  -v "$(pwd)/data/originals:/data/originals:ro" -v "$(pwd)/data/index:/data/index" employee-navigator:rag
```

Остановка: `docker stop employee-navigator`. Сборка без аргументов (`docker build -t employee-navigator .`) даёт прежний извлекающий режим без моделей: см. [приложение](#приложение-извлекающий-режим-и-прежние-проверки).

**Проверено ли.** Сборка образов RAG и запуск compose в среде разработки не проверялись: Docker здесь не запускался. Проверены статические тесты Dockerfile и compose. Сам конвейер проверен вне контейнера с тем же генератором (`llama-server` из llama.cpp на GPU) и тем же порядком старта (импорт папки, затем веб-сервис). Так получены ответы в разделе [«Сценарии использования»](#сценарии-использования).

## Архитектура

Один процесс Python: веб-интерфейс, импорт и поиск. Хранилище — один файл SQLite в `data/index/`. В профиле GPU генератор работает в отдельном контейнере `llm` (официальный сервер llama.cpp с CUDA). Порт `llm` наружу не публикуется: навигатор обращается к нему по адресу `http://llm:8080` внутри сети compose. В профиле CPU генератор работает внутри процесса навигатора (`llama-cpp-python`).

```text
 data/originals/ ──► импорт ──► SQLite: оригиналы, фрагменты, реквизиты, чанки, FTS5, векторы
                                                │
 браузер ──вопрос, дата──► поиск ──► reranker ──► контекст ──► генератор ──► проверка ──► ответ со ссылками
                                                                (llm)        утверждений
```

### Компоненты

| Модуль | Назначение |
| --- | --- |
| `app/autoimport.py`, `app/importer.py` | Импорт папки при старте. Контрольные суммы и версии; извлечение текста PDF и OCR сканов (Tesseract `rus`/`eng`); абзацы, таблицы и сноски DOCX; ячейки XLSX с заголовками строк и столбцов. Оригинал хранится в базе. |
| `app/requisites.py` | Реквизиты из текста документа: вид, номер, дата, дата введения. Связи редакций: изменяет, отменяет. |
| `app/chunking.py` | Чанки по дереву документа: разделы и пункты; строки таблиц — вместе с заголовками столбцов. |
| `app/retrieval.py`, `app/stemming.py` | BM25 в SQLite FTS5: основы слов Snowball, сокращения, определённые в самом корпусе («далее — СП»). |
| `app/dense.py` | Векторы `multilingual-e5-small` (ONNX Runtime); хранятся в той же базе. |
| `app/chunk_search.py` | Гибридный поиск: BM25 и векторы объединяются через reciprocal rank fusion с z-порогами. Отбор редакций, действующих на дату вопроса. |
| `app/rerank.py` | Cross-encoder `bge-reranker-v2-m3` переупорядочивает 20 лучших чанков. Его оценка служит сигналом уверенности. |
| `app/rag.py` | Контекст, вызов генератора по JSON-схеме, проверка утверждений, отказ и «вне темы». |
| `app/__main__.py` | Веб-интерфейс (`/`, `/ask`, `/fragment`) и команды `import`, `audit`, `embed`. |

### Поток документов

1. При старте `autoimport` обходит `/data/originals`. Файлы, уже импортированные с той же контрольной суммой, пропускает.
2. `importer` извлекает фрагменты — страницу PDF, абзац DOCX, строку таблицы — с локаторами (`#page/2/text-layer`, `#body/3/paragraph`, `#sheet/Структура/cell/B4`). Страницы без текстового слоя распознаются OCR; сомнительный OCR помечается для ручной проверки.
3. Из текста читаются реквизиты и связи редакций: какой приказ изменяет или отменяет документ, с какой даты.
4. Фрагменты режутся на чанки по пунктам и разделам. Для них строятся индекс FTS5 и векторы E5.

### Поток вопроса

1. **Проверка ввода.** Пустой вопрос и бессмысленный ввод отклоняются сразу.
2. **Поиск.** BM25 и векторный поиск по чанкам редакций, действующих на дату вопроса (без даты — на сегодня), затем переупорядочивание cross-encoder.
3. **Отказ до генерации.** Если лучшая оценка reranker ниже порога (`NAVIGATOR_ABSTAIN`, 0.003), сервис отвечает «Недостаточно данных». Если не найдено ничего, генератор только определяет, относится ли вопрос к работе: тогда «Недостаточно данных», иначе «вне темы».
4. **Контекст.** Чанки передаются с заголовками документов: реквизиты, пометка «изменён приказом № … с …» и подсказка о расхождении документов. Для многошаговых вопросов выполняется второй шаг поиска по найденному: например, подразделение → его финансодержатель.
5. **Генерация.** Генератор отвечает по JSON-схеме: краткий ответ, утверждения с номерами фрагментов, недостающие сведения. Текст документов в промпте — данные, а не инструкции.
6. **Проверка кодом.** Каждое утверждение сверяется с процитированным фрагментом:
   - числа, даты, номера, телефоны, инициалы, адреса и имена файлов должны совпасть целыми токенами. Число из заголовка документа засчитывается только как реквизит: дата, «№ 99», «Приложение 1»;
   - количество проверяется вместе с единицей измерения целиком (часы — не дни) и с направлением границы («не менее 12» — не «не более 12»);
   - слово, которое во фрагменте стоит только с «не» (или только без него), не может сменить знак: «не запрещено» по тексту «запрещено» не проходит;
   - фраза «в документах не указано» не показывается как факт — разве что сам фрагмент говорит то же самое («выплата премии не предусмотрена»);
   - слова предмета вопроса, которые утверждение повторяет, должны быть во фрагменте. Если слово отличается, генератору задаётся короткий вопрос, тот ли это предмет под другим названием. Уточнение, которое генератор опустил («актовый» в «актовый зал»), не проверяется.

   Неподтверждённое утверждение удаляется. Если не осталось ни одного, ответ становится отказом.
7. **Ответ.** Краткий ответ, утверждения со ссылками `/fragment?id=…&at=…` (фрагмент открывается с выделенным местом), недостающие сведения, источники с реквизитами и ограничения: изменения документа, расхождения.

Если генератор недоступен или вернул испорченный JSON, сервис отвечает извлекающим конвейером — цитатами найденных пунктов без генерации.

## Сценарии использования

Сценарии воспроизводятся на 16 вымышленных документах из `fixtures/rag/corpus.json`. Это учебные регламенты: поддержка, командировки, пропуска, закупки, дистанционная работа, структура подразделений, справочник телефонов. Реальные регламенты организации ими не подтверждаются.

Подготовка — отдельные папки, рабочие данные не затрагиваются:

```sh
mkdir -p data/demo/originals data/demo/index
docker compose --profile gpu build
docker run --rm --user "$(id -u):$(id -g)" -v "$(pwd)/data/demo/originals:/out" --entrypoint python \
  employee-navigator:rag-gpu eval/write_rag_corpus.py /out
NAVIGATOR_ORIGINALS_DIR=./data/demo/originals NAVIGATOR_INDEX_DIR=./data/demo/index \
  NAVIGATOR_UID=$(id -u) NAVIGATOR_GID=$(id -g) docker compose --profile gpu up
```

Вне Docker тот же корпус создаёт `python eval/write_rag_corpus.py data/demo/originals` (нужны пакеты `PyMuPDF` и `openpyxl`). Откройте http://127.0.0.1:8000/.

Ниже — фактические ответы на GPU (вне контейнера, той же конфигурацией). Формулировки генератора могут немного отличаться между версиями, но проверяемые факты и ссылки — те же.

### Сценарий 1. Многошаговый вопрос по двум документам

**Вход.** Вопрос: «Если закупку на 300 тысяч ведёт Центр вычислительных методов, кто подписывает заявку и каким способом закупать?». Дата не указана.

Ответ требует связать три факта из двух документов:
- порядок закупок (`procurement.pdf`) говорит, что заявку подписывает финансодержатель подразделения;
- таблица структуры (`structure.xlsx`) называет финансодержателя этого центра;
- тот же порядок задаёт способ закупки для суммы от 100 до 600 тысяч.

**Ожидаемый результат** (получен за 6.6 с):
- «Заявку на закупку подписывает финансодержатель подразделения» — ссылка на страницу 2 `procurement.pdf`;
- «Закупка стоимостью от 100 до 600 тысяч условных единиц проводится запросом котировок не менее чем у 3 поставщиков» — ссылка на страницу 1;
- «Финансодержатель Центра вычислительных методов — Орлова Н.В.» — ссылка на строку 4 листа «Структура» (`structure.xlsx`);
- блок «Источник» с реквизитами: «Порядок № 210-4 от 28.02.2024 · procurement.pdf», «structure.xlsx».

Ссылка открывает фрагмент с выделенным пунктом. Генератор также перечисляет, чего в документах нет («Недостаточно данных для части вопроса: …»). Этот список иногда избыточен — см. [ограничения](#ограничения).

### Сценарий 2. Изменённый документ и ответ на дату

**Вход.** Один и тот же вопрос «Сколько дней дистанционной работы в неделю разрешено?» дважды: без даты и с датой `2024-06-01`.

В корпусе есть положение № 120-1 («не более 2 дней в неделю», с 01.03.2024). Приказ № 610-2 заменяет эти слова на «не более 3 дней в неделю» с 01.01.2025.

**Ожидаемый результат без даты** (5.0 с). Краткий ответ: раньше разрешалось не более 2 дней; приказ № 610-2 от 15.12.2024 установил не более 3 дней с 01.01.2025. Утверждения ссылаются:
- на пункт положения (`remote.docx`, `#body/3/paragraph`);
- на пункт приказа с заменой слов (`remote-change.docx`, `#body/3/paragraph`);
- на пункт о вступлении в силу (`#body/4/paragraph`).

Источник положения помечен «изменён приказом № 610-2 с 01.01.2025». Отдельной строкой «Ограничение» предлагается сверить изменённые пункты.

**Ожидаемый результат с датой 2024-06-01** (3.5 с). «Разрешено не более 2 дней дистанционной работы в неделю». Ссылка ведёт только на положение № 120-1: приказ № 610-2 на эту дату ещё не действовал и в ответ не попадает.

## Переменные окружения и настройки

Значения по умолчанию в образе заданы в `Dockerfile` и `docker-compose.yml`. Секретов нет.

**Переменные compose** — задаются в оболочке при запуске, в контейнер не передаются:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NAVIGATOR_ORIGINALS_DIR` | `./data/originals` | папка документов; подключается только для чтения |
| `NAVIGATOR_INDEX_DIR` | `./data/index` | папка базы SQLite |
| `NAVIGATOR_UID`, `NAVIGATOR_GID` | `10001` | пользователь контейнера (Linux: `$(id -u)`, `$(id -g)`) |

**Аргументы сборки** (`docker build --build-arg …`):

| Аргумент | По умолчанию | Назначение |
| --- | --- | --- |
| `WITH_RAG` | `0` | `1` — эмбеддинги, reranker и генератор |
| `LOCAL_LLM` | `1` | `0` — генератор не входит в образ; в профиле GPU он работает в сервисе `llm` |
| `PIPELINE` | `extractive` | `rag` — ответ генератором по умолчанию |
| `RETRIEVAL` | `bm25` | `hybrid` или `dense` |
| `WITH_DENSE` | `0` | `1` — только модель эмбеддингов, без RAG |

Аутентификации в прототипе нет, поэтому порт публикуется только на `127.0.0.1`. Вопросы в HTTP-журнал не записываются.

## Качество

Золотой набор — вымышленный корпус `fixtures/rag` из 16 документов и размеченные вопросы разных типов:
- факты, таблицы, сроки;
- многошаговые и составные вопросы;
- редакции по дате;
- ложные посылки, вопросы без ответа в документах и вне темы;
- опечатки, разговорные и английские формулировки;
- попытки инъекций в вопрос.

Разметку проверяет `python eval/check_gold.py`, ответы оценивает `eval/measure_rag.py` (оценщик eval3). Конфигурация: гибридный поиск, reranker, Qwen3-4B на GPU. Два прогона одной конфигурации дали одинаковые тексты всех 301 ответа.

| Набор | Вопросов | Верно | Ложных | Пропусков | Отказы верно | Медиана / 95% |
| --- | --- | --- | --- | --- | --- | --- |
| tuning (настроечный) | 176 | 159 | 2 | 11 | 29/29 | 4.0 / 7.7 с |
| holdout v2 (регрессионный) | 60 | 51 | 0 | 7 | 13/13 | 4.1 / 7.6 с |
| holdout v3 (регрессионный) | 65 | 58 | 3 | 3 | 20/22 | 3.6 / 6.5 с |

Для сравнения, извлекающий конвейер без генератора (прежний оценщик): 85/52, 30/18, 26/27 (верно / ложных). Время ответа в прошлом прогоне тех же ответов было 3.0 / 2.6 с по медиане: оно зависит от состояния GPU.

**Как считается.** Факт засчитывается, только если он есть в утверждениях ответа: краткий ответ, пункты со ссылками, строки «Ограничение». Блок «Недостаточно данных для части вопроса» и строки «Источник» не в счёт. Ответ ложный, если в нём есть запрещённое утверждение, число или код не из процитированного текста, утверждение без ссылки или заявление «в документах не указано» при существующем ответе. Правила и их обоснование — в [журнале, итерация 42](sdd/quality-progress.md).

**Чего эти цифры не доказывают.**
- **Holdout v2 и v3 — регрессионные наборы, а не независимая оценка.** По ним проводились правки: v2 — с итерации 34, v3 — после единственного чистого прогона (55 верных, 6 ложных). Для честной итоговой оценки нужен новый закрытый набор.
- **Счётчик неподтверждённых утверждений узкий.** 0/254, 0/59, 0/76 значит только одно: числа, коды и адреса из утверждений есть в процитированном тексте. Применимость и смысловые связи он не проверяет.
- **Не все ложные ответы видны оценщику.** Свободный текст блока «Недостаточно данных» сервис пока не проверяет, а оценщик в него не смотрит. Числа там есть у 61, 24 и 13 ответов соответственно. Пример — W29: «кабинет не указан» рядом с правильно названным кабинетом.

Разбор по итерациям, отклонённые изменения и статистика — в [журнале качества](sdd/quality-progress.md).

Прогон на GPU-сервере вне контейнера:

```sh
llama-server -m data/models/qwen3-4b-instruct-2507/Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf -ngl 99 -c 16384 -np 4 --host 127.0.0.1 --port 8081
python eval/measure_rag.py --split tuning --config "rag=NAVIGATOR_PIPELINE=rag;NAVIGATOR_RETRIEVAL=hybrid;NAVIGATOR_LLM_URL=http://127.0.0.1:8081" --report eval/rag_results/<новый файл>.json
python eval/compare_runs.py eval/rag_results/tuning-eval3-baseline.json eval/rag_results/<новый файл>.json
python eval/measure_rag.py --split tuning --rescore eval/rag_results/<отчёт>.json --report eval/rag_results/<новый файл>.json
```

`--quick` берёт треть вопросов каждого типа (около 1.5 мин); полный tuning — около 5 мин. Существующие отчёты не перезаписываются.

Отчёт хранит полный HTML каждого ответа и хеш его разметки. Поэтому:
- `--rescore` переоценивает сохранённые ответы текущим оценщиком и разметкой без генератора;
- `compare_runs.py` исключает вопросы с изменённой разметкой и предупреждает о разных версиях оценщика.

## Ограничения

- **Только вымышленные данные.** Качество измерено на вымышленном корпусе. На реальных документах организации ответы не проверялись: это делает владелец данных локально ([инструкция](eval/owner-acceptance.md)).
- **Ложные посылки.** Посылку вопроса, которой нет в документах, генератор поправляет не всегда. Например, на «конференц-зал на 200 человек» он может ответить о бронировании, не указав, что зал вмещает 120.
- **Близкие предметы.** Если генератор опускает уточняющее слово («актовый зал» → «конференц-зал»), проверка предмета это не ловит.
- **Список «Недостаточно данных для части вопроса»** — свободный текст генератора, кодом не проверяется. Бывают лишние пункты и ложные утверждения: например, «кабинет не указан» рядом с правильно названным кабинетом.
- **Пробелы проверки утверждений.** Отрицание, оператор сравнения, единицу измерения, телефон, инициалы и номера из заголовка проверка теперь различает (итерация 43). Остаётся непокрытым:
  - уточнение, которое ответ опустил: телефон бухгалтерии корпуса А в ответ на вопрос о корпусе Г, конференц-зал вместо актового;
  - перенос свойства между предметами, когда утверждение собрано из двух фрагментов о разном (срок отдела закупок приписан комиссии).
- **Отказ вместо ответа.** Иногда (11 из 176 на tuning) сервис отказывает, хотя ответ в документах есть. Это сознательный перекос: лучше отказ, чем неподтверждённый ответ.
- **Изменения документов.** Связи редакций читаются из текста («внести изменения…», «признать утратившим силу»). Нестандартные формулировки могут быть не распознаны — тогда ответ помечает источник, но не выбирает редакцию.
- **Сканы и сложные таблицы.** Страницы сканов с сомнительным OCR и сложные таблицы требуют ручной сверки с оригиналом.
- **Нет авторизации и разграничения доступа.** Прототип не предназначен для эксплуатации с закрытыми данными без мер из раздела «Пилот».
- **Docker не проверялся.** Сборка образов RAG и запуск compose в среде разработки не выполнялись.

## Разработка без Docker

Нужны Python 3.11+ и Tesseract с языками `rus`, `eng`, `osd`:

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dense.txt
python tools/fetch_model.py e5 data/models/multilingual-e5-small
python tools/fetch_model.py reranker data/models/bge-reranker-v2-m3
python tools/fetch_model.py qwen3 data/models/qwen3-4b-instruct-2507
```

Генератор можно запустить двумя способами:
- **на GPU** — `llama-server` из официальной сборки llama.cpp с CUDA (github.com/ggml-org/llama.cpp, сверить SHA-256 со страницы выпуска), команда — в разделе «Качество»; затем `NAVIGATOR_PIPELINE=rag NAVIGATOR_RETRIEVAL=hybrid NAVIGATOR_LLM_URL=http://127.0.0.1:8081 python -m app`;
- **на CPU в процессе** — `pip install -r requirements-rag.txt` (нужны компилятор C/C++ и cmake), затем `NAVIGATOR_PIPELINE=rag NAVIGATOR_RETRIEVAL=hybrid python -m app`.

Импорт папки при старте: `NAVIGATOR_IMPORT_DIR=<папка>`. Тесты: `python -m unittest discover -s tests`.

## Пилот

Для пилота назначить владельца базы документов и заместителя. Они подтверждают источник, статус утверждения, границы действия и доступность приложений.

До пилота согласовать круг пользователей и права:
- загрузка и публикация — только назначенному оператору;
- доступ к ответам — по разрешённым документам, после реализации авторизации.

Выпуск редакции:
1. Оператор сохраняет оригинал в `data/originals/`. При следующем старте файл импортируется: изменённый файл с тем же путём — как новая версия, приказ об изменении — как отдельный документ, связь читается из его текста.
2. Оператор проверяет статус импорта и тестовые вопросы.
3. Владелец утверждает публикацию. Предыдущая версия и ссылки на неё сохраняются.

Нужны отдельные решения по отзыву доступа, журналам, резервированию и срокам хранения. Текущий прототип эти меры не реализует.

## Приложение: извлекающий режим и прежние проверки

Сборка без аргументов (`docker build -t employee-navigator .`) даёт извлекающий режим: BM25, без моделей, ответ — цитатами найденных пунктов. Этот режим проверен в контейнере, в том числе с `--network none`: [отчёт о поставке](eval/release-verification.md).

**Гибридный поиск без генератора:** `docker build --build-arg WITH_DENSE=1 --build-arg RETRIEVAL=hybrid -t employee-navigator:hybrid .`. Сравнение BM25 / dense / hybrid: [журнал качества, итерации 5–7](sdd/quality-progress.md), `python eval/measure_hybrid.py`.

**Локальный импорт для владельца данных** — архив в `data/originals/`, без сети:

```sh
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$(pwd)/data/index:/data/index" -v "$(pwd)/data/originals:/data/originals:ro" -v "$(pwd)/data/runs:/data/runs" -v "$(pwd)/sdd/sources/manifest.json:/app/manifest.json:ro" employee-navigator:mvp import /data/originals/input.zip --manifest /app/manifest.json --report /data/runs/import.json
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$(pwd)/data/index:/data/index" -v "$(pwd)/data/runs:/data/runs" -v "$(pwd)/sdd/sources/manifest.json:/app/manifest.json:ro" employee-navigator:mvp audit --manifest /app/manifest.json --report /data/runs/audit.json
```

Команда `audit` охватывает SRC-01–20; контрольную сумму SRC-00 сверяют отдельно. Инструкция и чек-лист: [eval/owner-acceptance.md](eval/owner-acceptance.md).

**Учебный показ извлекающего режима** на вымышленной фикстуре. Каталог загрузки заменяется, поэтому используйте отдельную временную папку:

```sh
docker build -t employee-navigator:contest-20261113 .
docker run --rm --network none --entrypoint python employee-navigator:contest-20261113 /app/eval/offline_probe.py --mode extractive
docker run --rm --network none --entrypoint python employee-navigator:contest-20261113 -m unittest discover -s tests -v
NAV_DEMO_DIR=$(mktemp -d /tmp/nav-demo-XXXXXX)
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113 import-fixture
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113 load-evidence fixtures/evidence/synthetic.json
NAV_DEMO_CONTAINER=$(docker run -d --user "$(id -u):$(id -g)" -p 127.0.0.1::8000 -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113)
NAV_DEMO_ADDRESS=$(docker port "$NAV_DEMO_CONTAINER" 8000/tcp)
python3 eval/check_demo.py --url "http://$NAV_DEMO_ADDRESS" --report "$NAV_DEMO_DIR/demo-check.json"
```

Остановка: `docker stop "$NAV_DEMO_CONTAINER"`. Учебные вопросы этого режима:
- «Не работает принтер, куда обратиться и что написать?» — шаги и ссылка `SYN-SUPPORT-v1-p3`;
- «Обычная многодневная командировка: когда подать документы и что делать после возвращения?» с датой `2023-01-01` — пункты `T1`, `T2`.

**Курируемые правила применимости** (`load-evidence`) связывают даты, условия и редакции с ID фрагментов импорта вручную; их подтверждает владелец данных ([eval/evidence-local.md](eval/evidence-local.md)).

**Репетиция на новой базе:** `docker run --rm --network none --entrypoint python employee-navigator:rehearsal-20261113 /app/eval/rehearse_demo.py`.

Прочие измерения прежних этапов: [поиск](eval/search-experiment.md), [сквозная синтетическая оценка](eval/end-to-end-benchmark.md).

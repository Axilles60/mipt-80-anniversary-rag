# Навигатор сотрудника

Сотрудник задаёт вопрос — сервис находит документы и пункты, собирает ответ из их текста (шаги по этапам для процедур, каналы и состав обращения, ограничения источника) и показывает ссылки на фрагменты с выделенным пунктом; если данных нет — прямо сообщает об этом. Документы импортируются кодом при старте контейнера. Качество проверено на вымышленных документах; на реальном корпусе его подтверждает владелец (см. [метрики на оригиналах](eval/owner-acceptance.md)). Применимость редакций по датам проверяется только при наличии курируемых правил. Актуальные ограничения и статус критериев: [матрица приёмки](eval/acceptance-matrix.md).

## Запуск: исходные документы + Docker

Всё — извлечение текста и таблиц, OCR сканов, разбиение на фрагменты, индекс и поиск — выполняет код в контейнере при старте; внешних сервисов нет, документы и вопросы не покидают машину. Нужен Docker Engine (интернет — только для сборки образа), около 3 ГБ места. Образ: Python 3.13, SQLite с FTS5, Tesseract `rus`/`eng`/`osd`, зависимости из `requirements.txt`. Один сервис; Compose не нужен. Документы и индекс в образ не входят.

1. Положите документы (PDF, DOCX, XLSX или ZIP с ними, можно во вложенных папках) в `data/originals/`.
2. Соберите и запустите (из корня проекта):

```sh
mkdir -p data/originals data/index
docker build -t employee-navigator .
docker run --rm --name employee-navigator -p 127.0.0.1:8000:8000 \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)/data/originals:/data/originals:ro" -v "$(pwd)/data/index:/data/index" \
  employee-navigator
```

Windows PowerShell: `docker run --rm --name employee-navigator -p 127.0.0.1:8000:8000 -v "${PWD}\data\originals:/data/originals:ro" -v "${PWD}\data\index:/data/index" employee-navigator`.

3. Дождитесь в журнале строк `Import: N file(s)` и `Import finished …: ok …, review …, error …`, откройте http://127.0.0.1:8000/. Остановка: `Ctrl+C` или `docker stop employee-navigator`.

При следующем запуске с тем же `data/index` неизменённые файлы пропускаются по контрольной сумме (`unchanged`); изменённый файл становится новой версией, новый — добавляется, без правки кода. Повреждённый или неподдерживаемый файл получает статус `error` с причиной и не мешает остальным. Без тома `data/index` индекс строится заново при каждом старте. Необязательный реестр с ID документов: `-v "$(pwd)/sdd/sources/manifest.json:/app/manifest.json:ro" -e NAVIGATOR_MANIFEST=/app/manifest.json`.

**Гибридный поиск (необязательно).** `docker build --build-arg WITH_DENSE=1 --build-arg RETRIEVAL=hybrid -t employee-navigator:hybrid .` — при сборке скачивается открытая модель `multilingual-e5-small` (ONNX, ≈490 МБ) с проверкой контрольных сумм (`tools/fetch_model.py`); при старте фрагменты кодируются локально. Без этого — BM25.

**Ответ генератором RAG — рекомендуемая конфигурация.** Документы — в `data/originals/`.

Генератор на видеокарте NVIDIA, ответ около 3 с:

```sh
docker compose --profile gpu up --build
```

Без видеокарты NVIDIA — один контейнер, генератор на CPU, ответ порядка 30–60 с (оценка, не замер):

```sh
docker compose --profile cpu up --build
```

Интерфейс — http://127.0.0.1:8000/, только на этой машине.

При сборке (нужен интернет) модели скачиваются с проверкой SHA-256:
- `multilingual-e5-small` — ≈490 МБ;
- cross-encoder `bge-reranker-v2-m3` int8 — ≈570 МБ, Apache-2.0;
- генератор `Qwen3-4B-Instruct-2507` q4_k_m — ≈2.5 ГБ, Apache-2.0.

Устройство режимов:
- **GPU.** Генератор работает в отдельном контейнере — официальный образ `llama.cpp` с CUDA, закреплённый по digest (`Dockerfile.llm-gpu`). Наружу он не публикуется; навигатор обращается к нему по имени сервиса `llm` внутри сети compose. Нужны драйвер NVIDIA с CUDA 12.4+ и NVIDIA Container Toolkit (Docker Desktop — WSL2 с поддержкой GPU). Видеопамять — около 5 ГБ.
- **CPU.** `llama-cpp-python` компилируется в отдельной стадии сборки (5–10 мин). Нужно ≈5 ГБ ОЗУ.

Если генератор недоступен, сервис отвечает извлекающим конвейером.

Без compose: `docker build --build-arg WITH_RAG=1 --build-arg PIPELINE=rag --build-arg RETRIEVAL=hybrid -t employee-navigator:rag .` — это вариант для CPU.

Качество на вымышленном золотом наборе — в разделе «Ответ генератором (RAG)» ниже и в [журнале](sdd/quality-progress.md). Сборка образов в данной среде не проверялась: проверены только статические тесты Dockerfile и compose.

Проверки внутри образа: `docker run --rm --network none --entrypoint python employee-navigator -m unittest discover -s tests -v`; учебный каталог и вымышленная фикстура для показа без реальных документов: `import-fixture`, `load-evidence fixtures/evidence/synthetic.json` (используйте отдельную папку индекса: `load-evidence` заменяет каталог).
### Локальный импорт для владельца данных

Поместите архив в `data/originals/`. Пример для локального реестра и архива, без сети на время импорта:

```sh
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$(pwd)/data/index:/data/index" -v "$(pwd)/data/originals:/data/originals:ro" -v "$(pwd)/data/runs:/data/runs" -v "$(pwd)/sdd/sources/manifest.json:/app/manifest.json:ro" employee-navigator:mvp import /data/originals/input.zip --manifest /app/manifest.json --report /data/runs/import.json
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$(pwd)/data/index:/data/index" -v "$(pwd)/data/runs:/data/runs" -v "$(pwd)/sdd/sources/manifest.json:/app/manifest.json:ro" employee-navigator:mvp audit --manifest /app/manifest.json --report /data/runs/audit.json
```

`input.zip` — имя, которое владелец задаёт сам. Команда `audit` охватывает SRC-01–20; SRC-00 — источник требований, его контрольная сумма сверяется отдельно. Импорт сохраняет оригинал как BLOB в локальной базе. Ошибки и требующие сверки страницы отмечаются; качество OCR и актуальность подтверждает владелец. Из-за ограничений импорта и поиска это не означает готовность ответов по корпусу. Инструкция и чек-лист: [eval/owner-acceptance.md](eval/owner-acceptance.md).

### Переменные и локальная модель

`NAVIGATOR_DB` — путь SQLite (в контейнере `/data/index/navigator.sqlite3`); `NAVIGATOR_IMPORT_DIR` — папка, импортируемая при старте (в контейнере `/data/originals`; вне контейнера по умолчанию не задана); `NAVIGATOR_MANIFEST` — необязательный реестр ID документов; `NAVIGATOR_RETRIEVAL` — `bm25` (по умолчанию), `hybrid` или `dense`; `NAVIGATOR_EMBED_MODEL` — папка модели эмбеддингов; `NAVIGATOR_DENSE_MIN_Z`, `NAVIGATOR_DENSE_GATE_Z` — пороги гибрида (2.5 и 1.2); `NAVIGATOR_OCR_DPI` — разрешение рендера страниц для OCR (300); `NAVIGATOR_OCR_LANG` — языки Tesseract (по умолчанию `rus+eng`); `HOST` — адрес прослушивания (`127.0.0.1` вне контейнера, `0.0.0.0` внутри); `PORT` — порт (8000); `NAVIGATOR_MODEL` — необязательное имя модели Ollama. Публикуйте порт только на localhost: аутентификации в прототипе нет. Переменных секретов нет.

Модель не входит в образ. Для запуска вне контейнера установите Python 3.11+, Tesseract с языками `rus`, `eng`, `osd` и зависимости: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`. На локальной машине Ollama можно заранее установить и загрузить `ollama pull qwen2.5:0.5b`; запустить эксперимент вне контейнера с `NAVIGATOR_MODEL=qwen2.5:0.5b .venv/bin/python -m app`. Адаптер подключается только к `127.0.0.1:11434`, поэтому модель на хосте не доступна контейнеру автоматически. Подключение Ollama к контейнерному сервису не подготовлено; контейнерный демонстрационный сценарий использует извлечение без модели. Реальный запуск модели не выполнен. Извлекающий режим проверен в контейнере с `--network none`.

## Воспроизводимые сценарии

Оба сценария используют только вымышленные документы и не подтверждают регламенты организации.

1. Вопрос «Не работает принтер, куда обратиться и что написать?» без даты. Ожидается учебный ответ с шагами и ссылками; первичная обработка за 16 рабочих часов не означает срок ремонта. Откройте ссылку `SYN-SUPPORT-v1-p3` и проверьте пункт в контексте.
2. Вопрос «Обычная многодневная командировка: когда подать документы и что делать после возвращения?», дата `2023-01-01`. Ожидаются вымышленные пункты до и после поездки с ID `T1`, `T2`, ограничения об утверждении и отсутствующем приложении. Откройте `T1`. Сроки и действительная процедура AC-DEMO-02 здесь не подтверждаются.

Произвольный вопрос «Как оформить отпуск?» должен дать сообщение о недостаточности данных. Для самостоятельной проверки измените вопрос, дату или категорию, откройте источник и сравните ответ с показанным вымышленным текстом. Свободный поиск по реальному корпусу не готов.

## Архитектура и ограничения

Поток документов: локальный оригинал → извлечение PDF/DOCX/XLSX и локальный OCR → фрагменты, локаторы и индекс SQLite; оригинал и версии сохраняются в базе. Страницы с неопределённым OCR и сложные таблицы требуют ручной проверки. Поток вопроса: форма → учебный FTS-поиск либо курируемые правила применимости → извлекающий ответ → ссылки на фрагменты. Для импортированных фрагментов с курируемыми правилами применимость проверяется по дате и категории до вывода; текст, локатор и ID правила должны совпасть с импортом. Без связанных правил выводится извлечение с предупреждением. Составной вопрос разделяется по вопросительным знакам, точкам с запятой и некоторым самостоятельным частям после «и»; общие объекты после инфинитивов переносятся эвристически, полнота не гарантируется. Для обычного импорта фрагменты до 12 000 символов выводятся целиком; более длинные не обрезаются до неполной нормы, вместо этого показывается недостаток контекста. Для неопределённых данных приложение должно уточнять условия или обозначать ограничения; полнота этого поведения пока не доказана. Вопросы не записываются в HTTP-журнал. Передача через внешние API не настроена.

Инструкции владельцу, включая сверку и известные пробелы: [eval/owner-acceptance.md](eval/owner-acceptance.md). Независимая синтетическая выборка поиска дала 1/3 фрагментов при k=3; содержательная точность по оригиналам не проверена.

## Демонстрация и пилот

Порядок: показать локальный запуск; выполнить два учебных вопроса, открыть подтверждения и показать статус недостаточности; дать проверяющему задать свой вопрос; явно обозначить, что AC-DEMO-01/02 и поиск по корпусу ещё не прошли приёмку. Дополнительная функция CASE-B03 не выбрана и не заявляется готовой.

Для пилота назначить владельца базы документов и заместителя, которые подтверждают источник, статус утверждения, границы действия и доступность приложений. До пилота согласовать круг пользователей и права: загрузка и публикация — только назначенному оператору; доступ к ответам — по разрешённым документам после реализации авторизации. При выпуске редакции оператор сохраняет оригинал и контрольную сумму, регистрирует основание изменения и период, проверяет извлечение и тестовые вопросы; владелец утверждает публикацию, предыдущая версия и ссылки сохраняются. Нужны отдельные решения по отзыву доступа, журналам, резервированию и срокам хранения. Текущий прототип не реализует эти меры и не предназначен для эксплуатации с закрытыми данными без них.

Результат проверенного чистого запуска и конфигурация: [eval/release-verification.md](eval/release-verification.md).

Для проверки применимости оператор локально связывает правила с ID фрагментов штатного импорта через `load-evidence`: текст и локатор должны точно совпадать с импортированными. Даты, условия и связи подтверждает владелец данных; автоматически из оригиналов они не выводятся. Веб-тест по синтетическим версиям: `.venv/bin/python -m unittest discover -s tests -p test_import_applicability_web.py -v`.

Для новых импортов DOCX сохраняются ссылки абзацев и строк таблиц на сноски; веб-источник показывает связанные сноски. XLSX показывает определённые эвристически заголовки строки и ветки столбца отдельно от соседних значений; структуру нужно сверять с оригиналом. Формула и сохранённое значение хранятся раздельно. Сомнительный OCR, неполный текстовый слой и формулы с `#REF!` исключены из подтверждённых норм и помечены. Ранее импортированные версии сохраняют прежние метаданные; для новой обработки используйте отдельную базу, не удаляя существующую. Проверка: `.venv/bin/python -m unittest discover -s tests -p test_context_web.py -v`.

Веб-измерение поиска по синтетическим импортированным документам, команды, результаты и оставшиеся ложные ответы: [eval/search-experiment.md](eval/search-experiment.md).

### Гибридный поиск (необязательно, локально)

По умолчанию поиск — BM25 (SQLite FTS5 с синонимами). Режим `NAVIGATOR_RETRIEVAL=hybrid` добавляет локальную многоязычную модель эмбеддингов: плотное ранжирование объединяется с BM25 через reciprocal rank fusion; фрагмент без общих слов с вопросом попадает в кандидаты, только если явно выделяется по близости (z-оценка ≥ 2.5, `NAVIGATOR_DENSE_MIN_Z`), а лексический кандидат, далёкий по смыслу (z < 1.2, `NAVIGATOR_DENSE_GATE_Z`), не становится пунктом ответа. `NAVIGATOR_RETRIEVAL=dense` — только плотный поиск (для сравнения). Вопросы и тексты не покидают машину; при отсутствии модели или библиотек сервис работает в BM25.

Подготовка один раз, с сетью (модель в образ и в git не входит, ≈490 МБ):

```sh
pip install -r requirements-dense.txt
mkdir -p data/models/multilingual-e5-small
for f in model.onnx tokenizer.json tokenizer_config.json special_tokens_map.json config.json; do
  curl -L --fail -o data/models/multilingual-e5-small/$f https://huggingface.co/intfloat/multilingual-e5-small/resolve/main/onnx/$f
done
```

Ожидаемый размер `model.onnx` — 470 268 510 байт. Другой путь к модели — `NAVIGATOR_EMBED_MODEL`. Дальше сеть не нужна: `NAVIGATOR_RETRIEVAL=hybrid python -m app embed` заранее кодирует фрагменты базы (иначе это происходит при первом вопросе; векторы хранятся в той же SQLite, новые документы кодируются по мере импорта без переиндексации остальных), затем `NAVIGATOR_RETRIEVAL=hybrid python -m app`. Контейнер не содержит этих библиотек и работает в BM25.

Сравнение BM25 / dense / hybrid на вымышленном корпусе (`fixtures/hybrid`: настроечные `tuning`, `holdout`, `holdout2` и отложенный `holdout3`): `python eval/measure_hybrid.py --split holdout3 --report eval/hybrid_results/<новый файл>.json`. Сводно по четырём наборам (76 вопросов) гибрид против BM25: верных ответов 40→46, ложных 17→11, пропусков 10→8, правильных отказов 9/20→11/20, время ответа 0.02→0.13 с; ни на одном наборе не хуже. Чистый dense даёт меньше всего ложных ответов (5), но больше пропусков. Таблицы, разбор по вопросам и ограничения: [журнал качества, итерации 5–7](sdd/quality-progress.md). Полный набор тестов в гибриде: `NAVIGATOR_RETRIEVAL=hybrid python -m unittest discover -s tests`. Порог откалиброван на синтетике; на реальном корпусе гибрид не проверен, поэтому он не включён по умолчанию.

### Ответ генератором (RAG, необязательно, локально)

`NAVIGATOR_PIPELINE=rag` включает конвейер RAG (`app/rag.py`):
- поиск чанков (`NAVIGATOR_RERANK=1` — переупорядочивание локальным cross-encoder);
- контекст;
- локальный `Qwen3-4B-Instruct-2507` Q4_K_M (Apache-2.0) в llama.cpp с ответом по JSON-схеме (до итерации 37 — `Qwen2.5-3B-Instruct`);
- проверка каждого утверждения кодом по процитированному тексту;
- при сбое — извлекающий ответ.

Модели скачиваются один раз:
- `python tools/fetch_model.py qwen3`;
- `python tools/fetch_model.py reranker`.

Два способа запуска генератора:
- **CPU, в процессе** (запасной режим образа): `pip install -r requirements-rag.txt`. Ответ — десятки секунд.
- **GPU, локальный `llama-server`** (для разработки и оценки). Ответ — около 3 с на RTX-классе. Нужна официальная сборка llama.cpp с CUDA для Windows (`llama-bXXXX-bin-win-cuda-13.x-x64.zip` и `cudart-…zip` с github.com/ggml-org/llama.cpp, сверить SHA-256 со страницы выпуска):

  ```sh
  llama-server -m data/models/qwen3-4b-instruct-2507/Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf -ngl 99 -c 16384 -np 4 --host 127.0.0.1 --port 8081
  NAVIGATOR_PIPELINE=rag NAVIGATOR_LLM_URL=http://127.0.0.1:8081 python -m app
  ```

  Адрес принимается только локальный (127.0.0.1/localhost): тексты не покидают машину.

Оценка на золотом наборе (`fixtures/rag`, 16 вымышленных документов, tuning 176 и holdout 160 вопросов; разметка проверяется `python eval/check_gold.py`):

```sh
python eval/measure_rag.py --split tuning --quick --config "rag=NAVIGATOR_PIPELINE=rag;NAVIGATOR_RETRIEVAL=hybrid;NAVIGATOR_LLM_URL=http://127.0.0.1:8081" --report eval/rag_results/<новый файл>.json
```

`--quick` берёт треть вопросов каждого типа (67 вопросов, около 1.5 мин на GPU) для итераций. Полный tuning — около 4 мин на GPU. Holdout прогоняется один раз на кандидата.

## Проверка нового документа без внешней сети

После сборки выполнить `docker run --rm --network none --entrypoint python employee-navigator:mvp /app/eval/offline_probe.py --mode extractive`. Команда создаёт синтетический DOCX и новую временную базу, импортирует документ, задаёт вопрос через веб и открывает ссылки. Сетевое пространство контейнера ограничено loopback; зависимости уже должны быть в образе. Метрики относятся к одному вымышленному вопросу.

Для отдельной проверки установленной модели на хосте: `ollama pull qwen2.5:0.5b`, затем `.venv/bin/python eval/offline_probe.py --mode model --model qwen2.5:0.5b --report data/runs/model-probe.json`. Если Ollama недоступна, выводится HTTP 503 и команда завершается с ошибкой; это не оценка качества модели. Адаптер используется для извлекаемых импортированных фрагментов, но не включён в ветку курируемых правил применимости. Подробная инструкция владельцу и шаблоны приёмки: [eval/owner-acceptance.md](eval/owner-acceptance.md).


## Подтверждённая конфигурация конкурсного показа

Используйте извлекающий режим без `NAVIGATOR_MODEL` и только синтетические данные. Сборка и проверка новой версии, включая новый импорт, вопрос вне базы и открытие выбранных цитат:

```sh
docker build -t employee-navigator:contest-20261113 .
docker run --rm --network none --entrypoint python employee-navigator:contest-20261113 /app/eval/offline_probe.py --mode extractive
docker run --rm --network none --entrypoint python employee-navigator:contest-20261113 -m unittest discover -s tests -v
```

Для интерактивного учебного показа из корня проекта создайте отдельный временный каталог. Команда загрузки каталога заменяет каталог в указанной базе, поэтому не используйте существующую рабочую базу.

```sh
NAV_DEMO_DIR=$(mktemp -d /tmp/nav-demo-XXXXXX)
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113 import-fixture
docker run --rm --network none --user "$(id -u):$(id -g)" -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113 load-evidence fixtures/evidence/synthetic.json
NAV_DEMO_CONTAINER=$(docker run -d --user "$(id -u):$(id -g)" -p 127.0.0.1::8000 -v "$NAV_DEMO_DIR:/data/index" employee-navigator:contest-20261113)
NAV_DEMO_ADDRESS=$(docker port "$NAV_DEMO_CONTAINER" 8000/tcp)
python3 eval/check_demo.py --url "http://$NAV_DEMO_ADDRESS" --report "$NAV_DEMO_DIR/demo-check.json"
printf 'Откройте http://%s/\n' "$NAV_DEMO_ADDRESS"
```

Откройте страницу и выполните два вымышленных сценария из раздела «Воспроизводимые сценарии», затем вопрос об отпуске. По окончании выполните `docker stop "$NAV_DEMO_CONTAINER"`: контейнер удалится, временная база останется. Интерактивный контейнер публикует порт только на loopback, но сам по себе не запущен с `--network none`; полностью изолированную сетевую проверку выполняет `offline_probe.py` выше. Ни учебные ответы, ни этот прогон не подтверждают реальные AC-DEMO-01/02. Результаты и границы проверки: [отчёт о поставке](eval/release-verification.md).

Независимо от прежних проверок поиска доступна [сквозная синтетическая оценка](eval/end-to-end-benchmark.md): `.venv/bin/python eval/measure_end_to_end.py`. Она отдельно выводит результаты настройки и отложенного набора, включая ложные ответы и ошибки цитирования; исходные результаты содержат выявленные дефекты.

## Репетиция на новой базе

Извлекающий режим подтверждён для синтетического примера. После подготовки зависимостей запустите репетицию в контейнере без внешней сети (из корня проекта):

```sh
docker build -t employee-navigator:rehearsal-20261113 .
docker run --rm --network none --entrypoint python employee-navigator:rehearsal-20261113 /app/eval/rehearse_demo.py
```

Скрипт создаёт временную базу и вымышленный DOCX, импортирует его штатной командой, открывает веб на loopback, измеряет точный вопрос, перефразировку и вопрос без ответа, затем импортирует новую версию и загружает вымышленный каталог с датами и связью редакций. Он сверяет исторический и новый ответы и повторно открывает старую цитату. В результате JSON содержит отдельные времена, статусы импорта и проверки; временная база удаляется после прогона. `review` для DOCX означает, что формат требует ручной сверки, а не ошибку импорта.

Короткий порядок показа: 1) сообщить, что документы и сроки вымышлены и используется извлечение; 2) запустить команду и показать результаты точного, перефразированного и отрицательного вопросов; 3) показать проверку выбора редакции и открытой старой цитаты; 4) обозначить предупреждение о ручной сверке и ограничения. Для интерактивного учебного показа используйте предыдущий раздел; этот автоматический сценарий не оставляет работающий веб-сервис. Проверенные времена и конфигурация приведены в [отчёте о поставке](eval/release-verification.md), действия владельца и форма локального отчёта — в [инструкции владельцу](eval/owner-acceptance.md). Измерения не подтверждают производительность машины конкурсной площадки.

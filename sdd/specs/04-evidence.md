# Редакции, доказательства и ограничения данных

Статус: производные требования к реализации CASE-03–07, CASE-T04, CASE-T07, CASE-T09–11. Реестр ниже содержит наблюдения по комплекту; подтверждение юридического статуса извне не выполнялось.

## Правила выбора источника

| ID | Требование |
| --- | --- |
| EVD-01 | Различать дату подписания, вступления в силу, период планирования, дату состояния справочника и дату файла. Имя файла/время изменения не являются достаточным основанием актуальности. |
| EVD-02 | Хранить явные отмены/изменения и их область действия. Более новый документ по другой теме не отменяет старый автоматически. Отмена одного пункта не равна отмене всего документа. |
| EVD-03 | Перед применением проверить категорию проекта/сотрудника, период, источник финансирования и специальные условия. Новую общую норму не смешивать с историческим маршрутом; специальное исключение не опускать. |
| EVD-04 | Для исторического вопроса выбирать применимую на запрошенную дату редакцию в пределах доказательств корпуса. При разрыве цепочки не утверждать полную историю действия. Для текущего вопроса отличать «последний найденный» от «достоверно действующий». |
| EVD-05 | Незаполненные реквизиты, недоступное приложение, OCR-сомнение и неразборчивый фрагмент сохраняются как ограничения ответа. Политика использования неутвержденных/неполных документов требует согласования; до этого в спецификации предлагается условное изложение с предупреждением о статусе. |
| EVD-06 | При противоречии показать оба основания и причину неопределенности. Если различие объясняется периодом, задачей планирования/возмещения или категорией, явно разделить ветки. Не создавать компромиссную норму. |
| EVD-07 | Ссылку документа на другой акт не считать наличием текста этого акта. Не переходить к внешнему содержимому автоматически и не отвечать по нему как по предоставленной базе. Пополнение корпуса — отдельный управляемый процесс. |
| EVD-08 | Форма, пример, поручение прошлой даты, лист согласования, подпись и действующая процедура — разные типы содержимого. Значения по умолчанию и ошибочные формулы не становятся нормативными требованиями. Сохранять дефекты перекрестных ссылок и нумерации. |
| EVD-09 | Перед внешним API установить открытый статус передаваемых документов, фрагментов и пользовательского вопроса. Если статус неизвестен — не передавать наружу до его определения; использовать допустимый локальный путь либо сообщить ограничение. Это предлагаемая реализация обязательного CASE-07. |
| EVD-10 | Политика CASE-07 распространяется на OCR, embeddings, LLM, внешнее хранение, телеметрию и журналы, а не только на генерацию ответа. Не пересылать содержимое в логи стороннего сервиса без той же проверки. |
| EVD-11 | Не требовать от сотрудника ФИО, телефоны и прочие сведения из бланка для простого справочного вопроса. При наличии в вопросе/источнике персональных сведений учитывать их перед любым внешним вызовом. Настройки доступа и сроки хранения согласовать отдельно. |

| GAP-14 | SRC-17 | Форма с диапазоном дат и фиксированным «Сальдо на 01.01.2023» | Не считать шаблон автоматически актуализированным на любой год |
| GAP-15 | SRC-12/SRC-18, SRC-13/SRC-19 | Повторение структуры и приложений | Одна содержательная основа, несколько представлений; сохранять обе ссылки |
| GAP-16 | SRC-13/SRC-19, приложение 7 | Ссылка на п. 12 «распоряжения», ставка прибыли в п. 21 приказа | Показать ошибку ссылки, отдельно подтвердить норму по п. 21 |
| GAP-17 | SRC-13, п. 8 | `finance-contact@example.invalid` | Не предлагать отправку на заведомо непригодный адрес |
| GAP-18 | SRC-14, п. 1 | Формулировка 90% «за вычетом накладных» | Без уточнения не выбирать между `0,9 × (сумма − накладные)` и `0,9 × сумма − накладные` для расчета |
| GAP-19 | SRC-14, п. 12 | Для штрафа 0,5% не названа периодичность | Не добавлять «в день» или «ежемесячно» |
| GAP-20 | Разные приказы | ФИО и названия руководящих ролей различаются | Цитировать роль/лицо в контексте источника, не выводить актуальное руководство из всех файлов вместе |
| GAP-21 | SRC-01, SRC-06, SRC-07, SRC-15 | Технические модели, контакты и рукописные реквизиты с OCR-ошибками | Сверять с изображением; пока неразборчиво — прямо сообщать |
| GAP-22 | SRC-03, SRC-07, SRC-15 | Текстовый слой может содержать только часть видимой страницы | Проверять полноту по изображению, распознавать всю страницу; не считать наличие нескольких строк полным извлечением |

## Отсутствующие ссылочные материалы

В комплект не входят полные тексты всех упомянутых положений о проживании/тарифах/пропускном режиме, прейскурант КМО, инструкции охраны труда, инструкции 1С, схема командирования № 1749-1, требования экспертизы № 2894-1, конкурсный регламент № 3188-1, маршрут № 1120-1, приказ открытия ФЛС 2020, справочник кодов финансодержателей, отдельные лимиты/процент накладных/тарифы, законодательные таблицы суточных и проживания, формы приказов/письма Минфина и перечень расходов гранта РФФИ. Система может сообщать, что на них есть ссылка, но не должна приписывать им неувиденные требования.

## Приемка

- AC-EVD-01: два разных периода/категории → разделенные правила с основаниями.
- AC-EVD-02: неопределенная редакция → соответствующая оговорка, без уверенного «действующий».
- AC-EVD-03: конфиденциальный либо неклассифицированный документ/вопрос → отсутствие исходящего содержимого во внешний API; допустимый локальный путь или явное ограничение.
- AC-EVD-04: форма с дефектом и нормативный приказ → дефект показан, ошибочный расчет не использован как доказательство.

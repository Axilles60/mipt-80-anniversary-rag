# Назначение и требования кейса

Основание: [SRC-00](../sources/SRC-00.md), разделы «Полное описание», «Ожидаемый результат», «Ограничения», таблицы критериев. Все `CASE-*` ниже — требования кейса. Само задание не предписывает конкретный стек, модель, векторную базу или способ авторизации.

## Цель и результат

| ID | Требование |
| --- | --- |
| CASE-01 | Принимать вопрос сотрудника на естественном языке и находить подходящий внутренний регламент или приказ. |
| CASE-02 | Давать краткий ответ на вопрос; если найденный документ описывает процедуру, формировать понятный, полный и логичный порядок действий. |
| CASE-03 | Основывать ответ на предоставленной базе документов, не дополняя его неподтвержденными общими знаниями модели. |
| CASE-04 | Указывать название каждого использованного документа и конкретный раздел, пункт или фрагмент, когда структура это позволяет. |
| CASE-05 | Отдельно сообщать, если в базе нет достаточной информации для ответа. |
| CASE-06 | Объединять несколько релевантных источников без противоречий; показывать обнаруженные противоречия и неоднозначности пользователю. |
| CASE-07 | Через любые внешние API передавать только открытые, неконфиденциальные данные. Наличие документа в архиве само по себе не подтверждает открытый статус. |

Пользователь базового сценария — сотрудник, задающий рабочий вопрос. Загрузка новых документов предусмотрена техническими критериями; кто выполняет ее и с какими правами — открытое решение. Предметные роли (руководитель проекта, ФЭУ, УРП и другие) нужны для выбора корректной ветки ответа; они не автоматически становятся ролями доступа приложения.

## Границы, предлагаемые к согласованию

Первая версия должна отвечать по всем темам предоставленного комплекта. Система объясняет действия, но кейс не требует самостоятельно отправлять обращения, бронировать зал, оформлять командировки, проводить платежи или изменять 1С. Эти интеграции не включаются в обязательный объем без отдельного решения.

Количество одновременных пользователей, время ответа, ограничения загрузки, требования к доступности, хранению истории, авторизации и конкретные дополнительные функции в материалах не заданы. Их нельзя представить как согласованные требования.

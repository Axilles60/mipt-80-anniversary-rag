# Приемка и воспроизводимость

Это план проверки будущей реализации. Код приложения, Dockerfile и Compose в этой итерации не создаются. Приведенные сценарии пока **не выполнялись**.

## Логическая архитектура для обсуждения

Поток документов: оригиналы → чтение и OCR при необходимости → структурированные фрагменты/таблицы и метаданные → связи редакций/приложений → поисковый индекс.

Поток вопроса: вопрос и существенные условия → поиск → проверка источников/редакции/полноты → формирование ответа → проверка подтверждения ключевых выводов → показ ответа, шагов и источников.

Контроль допустимости внешней передачи применяется перед каждым внешним обращением на обоих потоках. Ошибки чтения/поиска/генерации различаются. Названия компонентов здесь обозначают обязанности, а не отдельные сервисы или утвержденный стек. Локальная модель, внешний API для открытых данных, гибридный поиск, способы хранения и развертывания еще обсуждаются.

## Два обязательных демонстрационных сценария

### AC-DEMO-01 Обращение в техподдержку

**Вход:** «Не работает принтер на балансе МФТИ. Куда обратиться и что написать?»

**Ожидаемый результат:** приоритетная система обращений из `mipt.ru/it/support` либо `helpdesk@mipt.ru`; шаги подготовки ФИО, телефона, корпоративной почты, корпуса/кабинета, подразделения, описания и номера устройства при наличии. Указать первичную обработку не более 16 рабочих часов, не обещать устранение за этот срок. Если затрагивается ошибка информационной системы — указать форматы скриншотов. Источники: SRC-02, пп. 2.1, 3.1, 4.1–4.2; дополнительные условия только при их релевантности. Неформальный мессенджер не предлагается официальным каналом.

### AC-DEMO-02 Подготовка командировки

**Вход:** «Обычная многодневная командировка по России: когда подавать документы и что делать после возвращения?»

**Ожидаемый результат:** сообщить, что в предоставленном файле не заполнены реквизиты утверждения; изложить его порядок условно. Решение ф. 0504512, подтверждение цели, согласование по указанным ролям и передача в ОМС не позднее 7 рабочих дней; приказ, оформление поездки и сбор подтверждений. По возвращении за 3 рабочих дня — отчет 0504520 с копиями решения/приказа, подтверждениями и отчетом результатов, маршрутным листом при необходимости. Ссылки SRC-05, пп. 6, 46–54, 64–65; формы упомянуты, но не приложены. Не выдумывать схему № 1749-1. Однодневное исключение не применять к заданному входу.

Баллы конкурсной таблицы не являются измеренной точностью решения.

## Развертывание

- AC-DEPLOY-01: поставляется Dockerfile; для многокомпонентного решения Docker Compose. Запуск в чистом окружении по инструкции без правок исходного кода.
- AC-DEPLOY-02: README перечисляет ОС/аппаратные требования, версии/зависимости, команды запуска/остановки, настройки и все переменные окружения, внешние сервисы и условия их использования. Для обязательных моделей/индексов описывает получение/подготовку и требования к доступам.
- AC-DEPLOY-03: документация описывает архитектуру, обязанности компонентов, оба потока данных, ошибки и ограничения; содержит минимум два воспроизводимых use case с входом и ожидаемым результатом.
- AC-DEPLOY-04: способ демонстрации позволяет проверяющему задать свой вопрос, увидеть ответ, шаги и подтверждения. Документированные лимиты не выдаются за бесконечную масштабируемость.
